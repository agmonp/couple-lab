# בקרת איכות — Couple Lab בגישה מחקרית־התנהגותית

**תאריך:** 2026-08-12  
**סטטוס:** הממצאים בעדיפות גבוהה יושמו ונבדקו

המסמך משתמש בעקרונות המזוהים עם מחקרי Gottman כעדשת מוצר. הוא אינו מסמך רשמי של The Gottman Institute, אינו טיפול ואינו אבחון.

## מסקנה

הכיוון הנכון לאפליקציה הוא מאמן תרגול התנהגותי: לעזור לשני אנשים לפתוח בעדינות, להקשיב, לשקף, לתקן ולעצור בהסכמה. אין בסיס מספיק להפוך הבעת פנים או תנוחה לקביעה על רגש, הצפה או נסיגה. לכן המידע החזותי נשאר הקשר טכני חלש בלבד, ואילו פעולות משמעותיות דורשות שפה, סימון עצמי או פעולה מפורשת של המשתמשים.

## ממצאים ויישום

| עדיפות | ממצא | שינוי שבוצע |
|---|---|---|
| קריטית | תשובות אישיות נחשפו בעת העברת המחשב בין בני הזוג | נוסף מסך handoff שמסתיר את השאלון ודורש אישור האדם הבא, ברישום ובמפת הקשר |
| קריטית | המצלמה יכלה לתרום להסקה שנשמעת כמו מצב רגשי | visual observations אינם מעלים flooding, אינם יוצרים flooding/withdrawal tags ואינם מוסיפים נקודות חיוביות לציון התרגול |
| גבוהה | השאלה הופיעה בלי פרוטוקול שיחה מספיק ברור | נוסף כרטיס קבוע: פתיחה רכה → הקשבה → שיקוף → החלפת תור |
| גבוהה | מעבר התור ביקש רק “גם לענות” | האדם השני מתבקש לשקף ולבדוק שהבין לפני תשובתו; בסוף מוצעים שיקוף והערכה הדדיים |
| גבוהה | לא הייתה דרך ברורה לעצור עומס תוך התחייבות לחזור | נוסף כפתור הפסקה מפורש שקובע חזרה בעוד 20 דקות, מסמן cue ועוצר הקלטה פעילה |
| גבוהה | Insights והייצוא הציגו אחוזי “חום/מתח/נסיגה” | הוחלפו בפתיחות רכות, תיקוף, פניות שנענו ואיזון תורות |

## עקרונות המקור ששימשו לביקורת

- פתיחה רכה והמרת ביקורת לניסוח של תחושה וצורך: <https://www.gottman.com/blog/the-four-horsemen-the-antidotes/>
- מבנה דובר/מקשיב, שימוש במשפטי “אני”, שיקוף, תיקוף והחלפת תפקידים: <https://www.gottman.com/blog/effective-communication-in-a-relationship-5-ways-to-communicate-better/>
- בעת הצפה מדווחת: אות מוסכם, הרגעה עצמית והפסקה של לפחות 20 דקות לפני חזרה: <https://www.gottman.com/blog/the-four-horsemen-stonewalling/>

## בדיקות קבלה

- 23 בדיקות Vitest עברו, כולל regression חדש שמונע מרמזי מתח חזותיים לייצר flooding/withdrawal ומאמת שהפסקה מפורשת כן מפעילה תוכנית 20 דקות.
- `npm run build` עבר עם TypeScript ו־Vite.
- בדיקת דפדפן ידנית אישרה שהשאלון מוסתר לאחר מעבר מאגמון לתמר, שכרטיס הדובר/מקשיב מוצג ב־Practice ושכפתור ההפסקה מציג שעת חזרה.

## מגבלות שנותרו

- מסך ההעברה מגן מפני הצצה מקרית, אך אינו אימות זהות או הצפנה נפרדת לכל אדם.
- `SpeechRecognition` בדפדפן אינו תמלול מקומי מובטח; נדרש בעתיד מנוע תמלול offline כדי להבטיח עברית עקבית.
- face/voice enrollment עדיין אינו diarization בזמן אמת; שיוך הדובר נשאר ידני ומכוון בכוונה כדי להימנע מזיהוי שגוי.
